## Architecture
#### Compare and contrast the types of frontend development you used in your full stack project, including Express HTML, JavaScript, and the single-page application (SPA).
The front end development consists of two distinct client-side applications. The Travlr website, built with Express, renders JavaScript, HTML, and Handlebars templates directly in the browser. It organizes content into routes, views, and static files, delivering full pages from the server with injected database data.
In contrast, the admin page is a single-page application (SPA) powered by Angular. Its UI is structured into smaller, reusable components that combine to render the complete webpage. Upon initial visit, the SPA loads all necessary data and updates dynamically, eliminating the need for page reloads.
#### Why did the backend use a NoSQL MongoDB database?
MongoDB is a NoSQL database that stores information in flexible, JSON‑like documents, allowing each record to have its own structure. Its scalability makes it easy to add or modify fields during development, and it offers faster, more efficient querying compared to reading data directly from system files.
## Functionality
#### How is JSON different from Javascript and how does JSON tie together the frontend and backend development pieces?
JSON serves as a universal data format compatible with various programming languages. In web development, it enables seamless communication between a JavaScript frontend and the backend by providing a standardized structure. This process is typically managed by APIs, which bridge the gap between the user interface and the MongoDB database where the information is stored.
#### Provide instances in the full stack process when you refactored code to improve functionality and efficiencies, and name the benefits that come from reusable user interface (UI) components.
To streamline the frontend, I replaced complex DOM manipulation with Handlebars.js, allowing for the seamless insertion of backend JSON data into the UI. This architectural shift made the code more maintainable and scalable. In a full-stack environment where errors are frequent, this organized structure simplifies debugging and ensures the application can grow without becoming "spaghetti code."
## Testing
#### Methods for request and retrieval necessitate various types of API testing of endpoints, in addition to the difficulties of testing with added layers of security. Explain your understanding of methods, endpoints, and security in a full stack application.
RESTful APIs leverage standard HTTP methods—primarily GET, POST, PUT, and DELETE—to interact with specific resource endpoints for data retrieval and modification. To ensure system integrity, each endpoint requires rigorous validation to confirm it returns the expected status codes and handles edge cases gracefully.
In a modern full-stack environment, security protocols like JWT (JSON Web Token) authentication introduce an additional layer of testing complexity. Beyond verifying basic CRUD (Create, Read, Update, Delete) functionality, automated testing suites must simulate real-world security scenarios. This includes confirming that protected routes grant access to valid tokens while strictly rejecting unauthorized, expired, or malformed credentials. By automating these checks, developers ensure that the API remains both functional and resilient against unauthorized access.
